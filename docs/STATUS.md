  그래서 회전 대신 기존에 있는 4방향 스프라이트(`{color}_{north,south,east,west}.png`)를
  마우스 각도(90도씩 4구간)에 따라 갈아끼우는 방식으로 바꿨다 — 자세한 이유는 아래
  "스스로 판단해서 고친 부분" 참고. `world.tscn`에 `Camera2D`를 `Player`의 형제 노드로
  추가하고(부모로 넣지 않은 이유: Player의 scale=3이 카메라 줌에 그대로 곱해질 위험을
  피하기 위해), `_physics_process`에서 매 프레임 `camera.global_position`을
  `player_sprite.global_position`에 맞춰 카메라가 플레이어를 따라가게 했다.
  검수: `godot --headless --import`로 임포트 에러 없음 확인, `godot --path . --script`로
  임시 QA 스크립트를 실행해 (1) 초기 상태 (2) 마우스를 동쪽에 뒀을 때 east 스프라이트로
  바뀌는지 (3) 마우스를 북쪽에 뒀을 때 north 스프라이트로 바뀌는지 (4) 플레이어 위치를
  옮겼을 때 카메라가 따라가는지 4장의 스크린샷을 찍어 직접 눈으로 확인했다(모두 통과).
  WASD 자체는 `is_physical_key_pressed`가 실제 OS 키 입력에 의존해 헤드리스 스크립트로는
  직접 시뮬레이션할 수 없어서, 위치를 코드로 강제 이동시켜 카메라 추적 로직만 검증했다
  (이동 계산 로직 자체는 단순한 벡터 정규화+대입이라 별도 위험은 낮다고 판단). QA에 쓴
  임시 스크립트(`game/qa_movement.gd`)와 스크린샷(`/tmp/qa_world_*.png`), 테스트용
