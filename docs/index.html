#75 [BUILD] (버그 리포트, #74 QA 전체 스윕에서 발견) #68이 채집/채광 포인트(`resource_point.gd`)의 `Sprite`에 `z_index = -1`을 줘서 "월드 오브젝트가 UI보다 앞에 그려지는" 문제를 고쳤다고 완료 처리됐지만, **다른 종류의 월드 오브젝트에서 같은 증상이 재현된다** — UI `CanvasLayer`(`world.tscn`의 `UI`, `layer = 10`)가 항상 월드보다 위에 그려져야 하는데, 실제로는 화면 위치가 겹치면 여전히 뚫린다. 재현 1: `game/qa/full_sweep.gd`의 `farm_empty`/`farm_ready` 스텝(재실행하려면 `project.godot`의 `[autoload]`에 `QASweep="*res://qa/full_sweep.gd"`를 임시로 추가하고 `godot --path .`로 실행, `game/` 디렉터리에서 실행할 것)에서, 화면 좌상단 근처를 배회하던 사슴(`scenes/deer/deer.gd`, `z_index` 지정 없음=기본값 0)의 목/머리가 좌상단 "인벤토리: ..." HUD 텍스트 패널 위에 그대로 그려진다(픽셀 비교로 확인: 사슴의 갈색 픽셀이 패널의 어두운 초록 배경 위에 나타남, 텍스트를 가림). 재현 2: `mining_point` 스텝에서, 화면 하단에 있던 밭(`scenes/farm_plot/farm_plot.gd`, `Soil`/`Crop` 둘 다 `z_index = -1`)의 나무 울타리 테두리가 핫바 8번 슬롯의 좌상단 모서리 위에 그려진다. 두 경우 모두 서로 다른 노드 타입(AnimatedSprite2D/Sprite2D)과 z_index 값(0과 -1)인데 공통적으로 CanvasLayer(layer=10) UI보다 앞에 그려졌다는 점에서, 개별 노드의 z_index 문제가 아니라 `layer=10` 설정 자체가 이 렌더러(Godot 4.7.2, `gl_compatibility`)에서 화면상 위치/겹침 조건에 따라 완전히 보장되지 않는 것으로 보인다(#68이 검증했던 위치와 다른 위치/다른 노드에서 재현됨 — #68의 재검증이 모든 경우를 커버하지 못한 것일 수 있음). **추가 관찰(같은 원인일 수 있어 함께 적어둠)**: 밤(`world_night` 스텝, `TimeData.is_day=false`)에는 좌상단 HUD 패널의 배경색 자체도 낮보다 어두워진다(픽셀 실측: 낮 `(23,49,27)` → 밤 `(16,27,22)`, 잔디가 어두워지는 것과 같은 방향/비슷한 비율) — CanvasModulate가 월드용으로만 걸려 있어야 정상이라면 UI CanvasLayer 색상은 안 바뀌어야 하는데 실제로는 바뀐다. UI가 CanvasModulate의 영향을 받는 것과 CanvasLayer 순서가 안 지켜지는 것이 같은 뿌리(예: 이 렌더러에서 `layer=10` UI가 실제로는 완전히 분리된 별도 컴포지팅 패스가 아닐 수 있음)일 가능성이 있으니 함께 조사할 것. 원인을 코드로 직접 조사해서 고치고, 고친 뒤에는 사슴/밭이 좌상단 HUD와 겹치는 상황을 다시 재현해(플레이어를 그 근처로 이동시키면 됨) 스크린샷으로 확인할 것.
