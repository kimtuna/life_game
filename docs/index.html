(2) `scenes/world/world.gd`의 `_on_craft_pressed()`(940번째 줄 부근)가 재료를 먼저 소모한 뒤 `InventoryData.add_item(output, amount)`을 확인 없이 호출해서, 제작 시 인벤토리가 꽉 차 있으면 재료만 사라지고 결과물도 안 들어온다. **참고로 `scenes/storage_chest/storage_chest.gd`의 `try_transfer_to_player()`는 이미 `_inventory_has_room()`으로 미리 확인하고 공간이 없으면 아무것도 옮기지 않는 올바른 패턴을 쓰고 있다** — 이 패턴을 재사용/공통화한다. `InventoryData`에 공용 메서드(예: `has_room(item_name: String, amount: int) -> bool`, 또는 실제로 넣은 양을 반환하는 `add_item(item_name, amount) -> int`로 시그니처 변경)를 추가하고, `storage_chest.gd`의 `_inventory_has_room()` 로직을 여기로 옮겨 통합해도 된다(중복 제거, 선택). `dropped_item.gd`를 고쳐서: 주울 양이 인벤토리에 다 안 들어가면, **들어가는 만큼만 넣고 넣은 만큼만 `item_amount`에서 차감**하고(전부 못 들어가면 0개 처리, 아예 안 주움) 드롭 오브젝트는 남은 수량이 있는 한 사라지지 않게 한다(다음 프레임에 다시 시도). `_on_craft_pressed()`도 고쳐서: 재료를 소모하기 **전에** 결과물이 인벤토리에 들어갈 공간이 있는지 먼저 확인하고, 공간이 없으면 재료를 소모하지 않고 제작 자체를 실패 처리한다(버튼 옆에 "인벤토리 공간 부족" 같은 메시지를 잠깐 보여줘도 좋음, 필수는 아님). 실제로 인벤토리를 꽉 채운 상태에서 (a) 바닥 아이템을 밟아도 사라지지 않는지, (b) 제작을 시도해도 재료가 사라지지 않는지 확인한다.
